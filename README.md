# 按来源的 Token 用量

把输入框下方「用量」药丸点开的「Token 用量」弹窗，改成 **按模型 / 按来源** 的明细拆分，并保留各项合计。

## 显示什么

点开药丸后自上而下：

1. **按模型汇总**：每个 `provider/model` 一张卡片，直接列出五项精确整数——非缓存输入、输出、缓存读取、缓存写入、合计。同一模型的多次调用、主对话与子代理的调用会合并到一张卡片；不同 provider 分开。
   | 非缓存输入 | 输出 | 缓存读取 | 缓存写入 | 合计 |
2. **全部模型合计**：上面五项分别求和。
3. **按来源汇总**（可折叠）：主对话、上下文压缩、子代理各自的五项数值。
4. **口径说明**：合计 = 非缓存输入 + 输出 + 缓存读取 + 缓存写入。

其他行为：

- **所有数字都是千分位整数**，不再藏在鼠标悬浮提示里，触屏也能看。
- 药丸本身仍显示总量（「性能与用量 = 简洁」时改显示缓存命中百分比），**两种模式下药丸都可以点开**明细。
- 长模型名在卡片标题处换行，窄屏自动变成两列，面板按视口高度滚动，另有关闭按钮和 Esc 关闭。
- 「标题生成」不显示：这一版 DSH 的会话日志没有记录标题请求的 token 用量，无从统计。

## 数据从哪来

- **Host 投影** `usageBySource`：从会话日志折叠每条 `assistant/message` 的 provider/model 用量（来源＝主对话），以及 `compaction/summary` 自身那次模型调用的用量（来源＝上下文压缩）。重试按同一 turn/step 替换，不会重复计数。
- **子代理**：客户端从会话列表里找出 `origin = subagent` 的所有后代会话（不只直接子级），再取各自的 `usageBySource` 汇总。检查点写入有轻微延迟，刚跑完的子代理可能晚一轮才出现；插件安装前就已结束的子代理要等它被重新读取一次才有数据。
- 标题生成：DSH 没有把标题请求的 usage 写进会话日志，所以统计不到。

## 口径

- 四个桶来自 provider 上报的 usage，**互不重叠**：`inputTokens` 是非缓存输入，缓存读写单列。所以「合计」四者相加，缓存不会被算进非缓存输入，也不会被漏掉。
- provider 未单独上报缓存时按 0 计，明细里就是 0，不是估算值。
- 按来源汇总里「上下文压缩」只指**主会话**的压缩调用；子代理内部的压缩计入「子代理」。

## 安装

1. 「插件 → 添加插件 → 本地目录」，选择本目录。
2. 确认插件行已启用，然后**重启一次 DSH**（本次安装提示 restart-required：Host 投影在启动时挂载），重启后页面会重新装载前端模块。
3. 重启前药丸仍是内置的那一个；重启后没有 Host 投影时会退回只显示「合计」。

## 兼容性

- 依赖 DSH 0.2.2-rc.x 的 `sessionProjections` 注册表、`conversation.composer.dock` 的 `usage` 单元格，以及 `ui-chat` 的 `performanceUsage` 设置。
- 替换的是内置 `usage` 单元格（以 `priority: -1` 覆盖内置的 `priority: 0`）；关闭本插件后内置弹窗自动回来。

## 测试

```sh
node --test test/client-registration.mjs test/model-totals.mjs
```

`client-registration.mjs` 用 VM 跑前端模块、校验同单元格优先级覆盖与卸载还原；`model-totals.mjs` 直接加载生产代码里的聚合函数，校验合并去重与分列合计。另有 `test/replay.mjs` 需要真实会话日志作参数：

```sh
node test/replay.mjs <session.v4.jsonl.zstd>
```
